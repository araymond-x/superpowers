## Concerns

- **Fence-faithfulness vs. per-branch precision** (Deviation 1): the spawn-failed leg's warn text presumes a live successor, which is not always true on that leg. Flagging per `DONE_WITH_CONCERNS` convention since a future reader diffing the three warn blocks against each other (rather than against the fence) might read this as copy-paste drift instead of an instructed choice.
- **Bare `git commit` commits the whole index, not a pathspec.** `git add "$HOPS_FILE" "$SPAWN_LOG"` (+ conditionally the card) stages exactly those paths, but the subsequent `git commit -m ...` with no pathspec commits everything currently staged — which is fine today because Precondition 1 already refused a dirty tree before the spawn sequence began, so nothing else *should* be staged. But the window between that precondition check and this commit spans two 60s `wait_for_token` calls plus up to two 2s `sleep`s inside `run_post_spawn` — long enough that a concurrent process sharing the worktree could `git add` something else in between, and it would ride along into this commit. This is exactly what the plan's fence prescribes (`git add <paths>; git commit` with no pathspec on the commit), so deviating from it unilaterally would itself be a violation; recording it here as a residual risk rather than fixing it, since the fix (a pathspec on `git commit` or a stash/restore dance) is a design decision beyond this task's fence.
- **`tests/unit/spawn_handoff_helpers.py` edit is outside the stated Owned Files column** (Deviation 2) — flagged so a reviewer diffing against the write-scope table doesn't read it as scope creep; the plan's own Step 1 pseudocode instructs extending that stub, and no other consumer of the module was affected (verified by the full-suite run).
- **Pyright "not accessed" / type-inference diagnostics reported by the coordinator are confirmed pre-existing and unrelated to Task 13** (see Self-Review) — not fixed, since fixing them would mean editing `_outcome()` and its ~15 downstream call sites, none of which are in this task's write scope, for a static-analysis artifact with no runtime effect and no repo convention (`type: ignore`, `pyrightconfig.json`) to reconcile it against. Recommend a separate, appropriately-scoped cleanup task if this is to be addressed.
